# main (receiver)

## Обзор

`receiver/main.cpp` — точка входа GUI-приёмника: настройка приложения и тёмной темы, разбор аргументов, создание окна и рабочего потока приёма, проводка сигналов и запуск цикла событий.

## Настройка QApplication

`QApplication` (виджетное приложение), имя и версия заданы. До создания окна: стиль `Fusion` и тёмная `QPalette`, собранная из семантических ролей `Theme.h` (`window`, `surface`, `gaugeFace`, `textPrimary`, `ok`, `textDim`...), включая роли `Disabled`.

## Обработка аргументов командной строки

| Опция | По умолчанию | Описание |
|-------|--------------|----------|
| `-p` / `--port` | `12345` | UDP-порт для приёма |

Значение порта проверяется через `toUShort(&ok)`; невалидное или нулевое — сообщение в stderr и выход с кодом 1 (не молчаливый переход на ephemeral-порт).

## Создание объектов верхнего уровня

- `MainWindow window` — стековый объект главного окна (уничтожается после остановки рабочего потока).
- `workerThread` (`QThread`, `new`) — поток приёма; удаляется вручную после `quit()`/`wait()`.
- `UdpWorker *worker` — создаётся без родителя и переносится на поток через `moveToThread`.

## Проводка соединений

`started → start` (воркер стартует в своём потоке), `finished → deleteLater` (владение жизненным циклом воркера), `dataReceived/errorCountChanged/errorOccurred → слоты MainWindow` с контекстом `&window` — queued-доставка в GUI-поток.

## Цикл событий и завершение

`app.exec()`; после выхода — `workerThread->quit()`, `wait()` с таймаутом 2 с (с предупреждением при зависании), удаление потока, возврат кода `exec()`. При ошибке bind воркера `MainWindow::onLinkError` вызывает `qApp->exit(1)` — деструктивный путь проходит ту же последовательность очистки.

## Зависимости

`MainWindow.h`, `UdpWorker.h`, `Theme.h`; Qt: `QApplication`, `QCommandLineParser`, `QPalette`, `QThread`, `chrono`.
