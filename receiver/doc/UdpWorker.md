# UdpWorker

## Обзор

`receiver/UdpWorker.h/.cpp` — приёмник UDP-датаграммов, живущий на отдельном `QThread` (см. `receiver/main.cpp`). Создаёт `QUdpSocket`, привязывается к заданному порту, читает входящие датаграммы, прогоняет их через `TelemetryPacket::unpack` и рассылает результаты сигналами. Весь обмен с GUI-потоком — только через сигналы: непосредственно UI-классы воркер не знает.

## Зависимости

Модули Qt: `Qt6::Network` (`QUdpSocket`), `Qt6::Core` (`QObject`, `QDebug`). Проектный тип: `TelemetryPacket` из статической библиотеки `common`. Тесты подключают файл напрямую: `tests/test_udpworker.cpp` компилирует `../receiver/UdpWorker.cpp` (см. `tests/CMakeLists.txt`).

## Иерархия и роль

Наследует `QObject` — метаобъектная система (сигналы/слоты), без визуальной части. Экземпляр создаётся без родителя в `main()` и переносится на рабочий поток через `moveToThread`; жизненным циклом управляет соединение `QThread::finished → deleteLater`.

## Сигналы

#### dataReceived(TelemetryPacket pkt)

Успешно распознанный пакет. Аргумент передаётся по значению — копия создаётся в момент постановки queued-события, слот получателя выполняется в его потоке (для `MainWindow` — в GUI-потоке). Обработчик ожидается обновляющий отображаемые данные.

#### errorOccurred(const QString &message)

Неустранимая ошибка запуска: не удалось привязать сокет к порту. Строка содержит порт и `errorString()` сокета. Текущий обработчик (`MainWindow::onLinkError`) показывает `QMessageBox` и завершает приложение. Сигнал испускается один раз, после чего воркер остаётся без сокета.

#### errorCountChanged(int count)

Очередной датаграмм отбракован (неверный размер, magic или CRC, либо ошибка чтения). Аргумент — накопленное число ошибок с начала работы. Обработчик ожидается обновляющий счётчик и статистику линии.

## Публичные слоты

#### void start()

Создаёт сокет и привязывает его к порту из конструктора. Идемпотентен: повторный вызов при живом сокете ничего не делает. При неудачном `bind()` испускает `errorOccurred`, освобождает сокет и возвращается. Вызывается через соединение `QThread::started`, то есть в контексте рабочего потока.

#### void stop()

Закрывает сокет и планирует его удаление через `deleteLater()`. Вызывается из деструктора воркера; публичный статус слота оставлен для явной остановки в будущем.

## Публичные методы

#### quint16 boundPort() const

Фактически занятый порт (`QUdpSocket::localPort()`), `0` — если сокета нет. Основной сценарий — тесты, запускающие воркер с портом `0` (ОС выделяет свободный).

## Владение и жизненный цикл

Воркер создаётся без родителя (требование `moveToThread`) и удаляется соединением `finished → deleteLater` рабочего потока. Сокет — ребёнок воркера, создаётся в `start()` и освобождается в `stop()`/деструкторе. Деструктор `~UdpWorker()` вызывает `stop()`.

## Поточность

Все методы воркера выполняются в его рабочем потоке: `start()` — по сигналу `started`, `onReadyRead()` — по `readyRead` сокета, деструктор — при обработке `DeferredDelete` при завершении потока. Состояние (`m_socket`, `m_errorCount`) не защищено примитивами синхронизации и не должно трогаться из других потоков; наружу уходят только копии через сигналы.

## Взаимодействие с другими классами

См. `receiver/main.cpp`: сигналы подключены к слотам `MainWindow` (`onTelemetryReceived`, `onErrorCountChanged`, `onLinkError`) с `&window` в качестве контекста — доставка queued в GUI-поток.

## Внешняя связь

UDP-сокет, только входящий трафик (в ответ ничего не отправляется). Формат данных — 46-байтовые пакеты `TelemetryPacket`; датаграммы другого размера отбраковываются целиком по `pendingDatagramSize()` ещё до чтения. Отправитель — утилита `sender` из этого же проекта (по умолчанию 127.0.0.1:12345, 20 Гц).

## Пример использования

```cpp
auto *thread = new QThread;
auto *worker = new UdpWorker(12345); // без родителя: дальше moveToThread
worker->moveToThread(thread);
QObject::connect(thread, &QThread::started, worker, &UdpWorker::start);
QObject::connect(thread, &QThread::finished, worker, &QObject::deleteLater);
QObject::connect(worker, &UdpWorker::dataReceived, window, &MainWindow::onTelemetryReceived);
thread->start();
```
